# Project state

Epic intent lives in `docs/project-goals.md`, ownership in `docs/codemap.md`, open bugs in
`docs/issues/`, and which reverse-engineering steps are ground-truth-ready and which are not in
`docs/re-frontier.md` (read through `tools/re_frontier.py`).

**Comparison baseline**: the unmodified USA PlayStation release `SLUS_008.93` in a general-purpose
emulator. Intended deltas: a standalone native/dynarec product, host-owned finite frame iteration,
native input and render ownership, true widescreen, interpolated 60 fps.

**Current focus**: G004 loading removal (S015). The v1 route is inventoried and carries no
loading-only presentation; the one load still unmeasured is the post-level transition
`0x8007BC74(4, 0x40)`, which no verified route reaches. Playing a level to completion is ABANDONED
(issue 0039), and RE-21 settles the alternative: the level gate is the persisted byte
`0x800C1628 + cursor`, written only by the level-completion path, and there is no cheat. The game DOES
offer a no-input route to several later areas: idle at the title and attract mode rotates levels
0/3/7/10/13 (verified loading an arcade interior and a Wild West barn yard). Level index 1 is not in
that rotation, so the second level specifically stays unreachable, and `0x8007BC74(4, 0x40)` remains
unmeasured by it. Inventorying those attract level loads for G004 is the next step.
MEASURED on the attract route: idle-at-title loads the arcade interior (~frame 3200) and the Wild West barn yard with the guest's own `DEMO MODE` text (~frame 5900), returning to the title between. Its inter-level black window (~frames 3500-4800, 0.00% non-black throughout) is NOT a loading-only wait: pressing Start at frame 4000 ends it by 4100, where unpressed it persists past 4400 and resumes only at 4800, so it is Start-cancellable authored presentation (an FMV, which headless cannot show — issue 0040 — or the demo's own cutscene), not a load. 4:3 at 960x720.
Attract-route load inventory (4:3, 100-field cadence, 32 captures): content to 3200; the game's own "LOADING..." CARD at ~2100-2300; fully black 3300-4600 (the Start-cancellable inter-level movie); title returns 4700-5100. The card's OWNER IS NOT YET IDENTIFIED and the obvious candidate is RULED OUT: a title-native override installed at overlay `FUN_800DB54C` (screen 4) and instrumented with a temporary probe was never entered on this route, so screen 4 is not this card. `FUN_8007BC74` is called only from `FUN_8007A9E8`, with screen ids 10, 2, 5, 0xb, 4, 9, 8; id 4 is requested only on the LEVEL-COMPLETION path, not the attract path, so the attract card is one of the remaining ids (8, 5 or 9). A SECOND owner hypothesis is also RULED OUT by measurement: a temporary probe installed at the overlay screen dispatcher `FUN_800D95C4`, logging the screen id and then calling the original through `callOriginalToReturn`, shows the attract route requests only ids 10 and 2 and never any card screen. So the LOADING card is drawn OUTSIDE `FUN_8007BC74`'s dispatcher entirely and its owner is still unidentified. The probe was removed and both overrides reverted, not shipped. STATICALLY, the card's art is `GFX/LOADING.RAW` (10,932 B, RNC2-compressed), named in MAIN's asset-name table at 0x80021EA8 as `gfx\loading.raw`, in a table with `gfx\film.raw`, `gfx\level1a.raw` and a leading `bin`. So the card is a MAIN-side asset drawn outside the overlay screen dispatcher, which is consistent with the probe finding. CORRECTED BY RE-22 (owner now known, still not fixed): `--refs 0x80021E94` returns one reference, `addiu a0,a0,0x1e94` at 0x8003FB5C in `FUN_8003FB0C`, the scene-graphic selector whose `case 0` is `gfx\loading.raw`. Its only callers are `FUN_800412F0` and `FUN_8007C278`. `FUN_8007C278(param_1, param_2)` opens `if ((param_2 != 0) && (param_2 != 0x7b)) param_1 = 0;` and is called from the level start as `FUN_8007C278(DAT_800A16A8, DAT_800A120C)` -- and `DAT_800A120C` is the attract/demo flag. So on the attract route the guard forces graphic id 0, loads `gfx\loading.raw`, and presents it for the level start's first 28 fields. This CORRECTS RE-20: those fields are a loading-only screen under demo mode, not a pure authored fade. The owner is `FUN_8007C278`; no override is written yet.
16:9 at 1280x720 in the demo hallway and barn yard: both margins show real scene (wallpaper, stairs, barn wall), no pillarbox, no visible stretch, the yellow DEMO MODE caption keeps its shape, and the guest core (columns 160-1119) differs from the 960x720 4:3 capture by 13.18 and 11.52 mean |delta|/255 over 2,073,600 samples, BELOW the synthetic horizontal-stretch control for the same content (19.88 and 16.26) -- suggestive of a widen rather than a stretch, but the separation is weak because the two runs are separate animated runs, so this is NOT a decisive non-stretch proof. No cull or rect limit fault found; nothing changed. FPS60 in the demo hallway (16:9, `fps60guest` census): 91.60% resolved over 631,118 polygons across 661 frames carrying geometry, 3.53% unmatched, 4.87% ambiguous. DO NOT CHASE THESE NUMBERS: the 'ambiguous' and operand-matching figures measure exactly the vertex-identity GUESSING that has been ruled out. psxport is being changed (spyro3-wide) so only producer-DECLARED identity pairs are used and an undeclared vertex draws at its real position, which retires that metric. Until TS2's producers declare identity, this figure is not a quality measure and FPS60 pairing work is parked. The one durable finding here: NO DUPLICATE FRAMES -- 11 consecutive presents differ by 7.97-11.76 mean |delta|/255, so no in-between repeats either neighbour.
